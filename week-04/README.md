# Неделя 4 — nginx как reverse proxy перед контейнером

**Итог:** сайт `borisov-devops.ru` отдаёт контейнер, а nginx на хосте держит HTTPS и HTTP/2 и пересылает запросы внутрь. Этап 3 «Контейнеры» закрыт.

```
браузер ──HTTPS, HTTP/2──▶ nginx на хосте (443, TLS)
                              │ proxy_pass
                              ▼
                         127.0.0.1:8080 (порт из Compose)
                              │
                              ▼
                         контейнер site (nginx:alpine, порт 80)
```

Порт контейнера опубликован только на `127.0.0.1` — снаружи до него не достать, только через nginx на хосте.

## Что сделано

| Задача | Как проверил | Результат |
|---|---|---|
| Прокси перед контейнером | запрос виден в логе контейнера, в ответе — `index.html` из образа | `200` |
| Тест на отказ | `docker compose stop site` → `curl -I` | `502 Bad Gateway`, после `start` — снова `200` |
| Продление сертификата | `certbot renew --dry-run` | success |
| HTTP/2 | `curl -I --http2` | `HTTP/2 200` |
| AAAA для `www` | `dig AAAA www... @ns1.timeweb.ru`, `curl -6` | адрес отдаётся, `200` |
| `/etc/netplan` в бэкапе | `tar -tzf` свежего архива | файлы внутри, права архива `-rw-------` |

Конфиг nginx — в файле `nginx-borisov-devops.ru.conf` рядом.

## Что сломалось и как чинил

### 1. IPv6 пропал с сервера (28.10)

**Симптом:** `ip -6 addr show scope global` — пусто, а AAAA-запись в DNS по-прежнему указывала на старый адрес. Клиенты с IPv6 стучались в пустоту.

**Причина:** адрес был получен по DHCPv6 и уже 12.10 был помечен `deprecated`. Маршрут по умолчанию в IPv6 приходит из Router Advertisement, а файл `51-dhcp6.yaml` из образа провайдера ставил `accept-ra: false`. Аренда истекла — адреса не стало.

**Решение:** свой `/etc/netplan/99-ipv6.yaml` — статический адрес `/128`, `dhcp6: false`, маршрут `::/0` через шлюз провайдера с `on-link: true`. Применял через `netplan try`: если бы связь пропала, через 120 секунд всё откатилось бы само. Бэкап старых конфигов сделан заранее, `dhcpcd6` отключён. Проверил перезагрузкой: nginx, ssh и fail2ban поднялись, сайт отвечает `200` по IPv4 и IPv6 (`2a03:...`).

**Вывод:** сеть на удалённом сервере меняю только с бэкапом, веб-консолью под рукой и через `netplan try`.

### 2. Сломанный конфиг лежал на диске, а сайт работал

При первой попытке я вставил строки `proxy_pass` и `proxy_set_header` **после** закрывающей скобки старого `location / { try_files ... }`, то есть прямо в блок `server`. `nginx -t` ответил:

```
"proxy_pass" directive is not allowed here
```

Команды были связаны через `&&`, поэтому `reload` не случился, и nginx продолжил работать на старом конфиге в памяти. Сайт отвечал `200`, но на диске лежала мина: при первой перезагрузке сервера nginx бы не поднялся.

**Решение:** нашёл проблему через `nginx -t` и `cat -n`, поправил одной командой `sed` по номерам строк — закомментировал `root`, удалил `try_files`, перенёс закрывающую скобку. Проверил глазами, потом `nginx -t` и `reload`.

**Вывод:** `200` от сайта не доказывает, что конфиг на диске рабочий. Доказывает `nginx -t`.

### 3. Как доказать, что страницу отдаёт контейнер

Одного `200` мало: его отдавал бы и старый `root`. Проверял двумя способами:

- в логе контейнера появилась строка `"HEAD / HTTP/1.0" 200 ... "curl/8.5.0"` — `HTTP/1.0` и есть подпись nginx на хосте, который ходит к контейнеру через `proxy_pass`;
- в конце страницы — тестовые комментарии, которые есть только в `index.html` образа.

### 4. 172.18, а не 172.17

В логе контейнера адрес клиента — `172.18.0.1`, а не `172.17.0.1`, как я ожидал по опыту с `docker run`. Compose создаёт свою сеть `site-docker_default` со своей подсетью, это не `docker0`. Поэтому настоящий IP посетителя контейнер видит только в заголовке `X-Forwarded-For`, его nginx на хосте передаёт.

### 5. Запись в панели есть, а DNS её не отдаёт

После добавления AAAA для `www` панель Timeweb показывала запись, а `dig @ns1.timeweb.ru` возвращал пустоту. Ошибки в записи не было: имя без задвоения, адрес верный. Через некоторое время оба nameserver начали её отдавать.

**Вывод:** DNS проверяю у авторитетного сервера через `dig @ns`, а не по панели.

## Команды, которые пригодились

```
sudo nginx -t && sudo systemctl reload nginx
curl -sS -I https://borisov-devops.ru
sudo docker compose logs --tail 3 site
sudo docker network inspect site-docker_default | grep Subnet
dig AAAA www.borisov-devops.ru @ns1.timeweb.ru +short
sudo certbot renew --dry-run
```
